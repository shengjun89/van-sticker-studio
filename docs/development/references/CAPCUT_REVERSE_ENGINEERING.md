# CapCut 画布研究：房车产品的交互参考与证据边界

研究快照：2026-10-27。适用对象：van-sticker 产品、设计与研发团队。

本文是可同步团队仓库的概念级摘要，不是 CapCut 复刻规格、接口接入说明或可重放的逆向工程包。可借鉴的是画布、上下文引用、异步结果与版本管理的产品组织方式；房车领域模型、后端契约及 AI 服务接入必须独立设计。

## 1. 阅读口径

全文使用三种标记，避免把源码存在、运行观察与新产品建议混为一谈：

- **已观察**：原研究记录了实际 UI 操作及可见结果；范围只限列明的子动作，不代表后端协议或所有分支已验证。
- **静态推断**：来自保存的发布包、局部处理器、状态分支或 REA 静态分析；不代表入口当前可达、服务端接受请求或任务执行成功。
- **建议**：面向房车产品的独立设计取舍，不是对 CapCut 实现的事实断言。

出处使用文末的 `S1`—`S5` 编号、文件名和 SHA256。原始研究包不随本文同步，也不设置指向本机文件或未发布材料的链接。

## 3. REA 与网络协议的明确边界

### 3.1 语义图并未恢复完整调用关系

**静态推断**：REA 6.8.0 生成的语义图标记为 `partial`、`truncated`，记录 117,276 个节点、142,813 条关系和 47,842 个 unknown；部分模块触及每文件 30,000 个语义节点的保留上限。这些是静态图统计，不是用户行为或请求计数。`S3`、`S4`。

**静态推断**：对 `readLink`、`copyNodes`、`addMaterials`、`combineToStoryboard` 分别执行 callers 与 forward-influence，共 8 次属性查询。查询均成功返回，但各次保留的已解析关系均为 0，`resolved_call_chains_recovered=false`。其中 `combineToStoryboard` 的 callers 状态 `found` 只表示命中了种子，不表示找到调用边。`S3`、`S4`。

这不等于源码没有字面调用或 UI 没有实际行为；也不能反向声称这些方法的完整调用链已恢复。原报告中的“入口→校验→局部调用→结果”是人工结合字面处理器与局部源码整理的候选链路，不是完整语义图自动证明。

### 3.2 静态分析不是 HAR、WS 帧或 SSE 实录

**已观察**：原研究保留了 UI 行为和前端异常观察，但没有保存 HAR、请求/响应正文、SSE 原文或 WebSocket 帧，也没有重放私有接口。`S2`、`S3`。

因此以下关系尚未被端到端实证建立：聊天消息与工具调用的关联、主任务与子任务的请求关联、任务与最终产物的关联、每次变更与成功保存版本的关联，以及报价与最终账单的关联。界面显示成功、消息流结束、主任务就绪和所有产物成功是不同条件。

**静态推断**：源码存在流式会话、任务监控、轮询回退、取消与恢复机制；这些可以提示设计需要覆盖的状态，但不能照搬为已验证的实时协议。客户端立即报告“已中断”也不等于服务器确认停止；轮询回退计时不是整个生成任务的超时。`S5`。

复跑条件也有限制：原研究记录的 Node 版本不在 REA 声明的支持范围内。即使静态命令退出成功，后续复核仍宜使用其支持的运行环境。`S3`。

## 5. 房车 P0 的应用边界

本节是**项目约束与建议**，不是 CapCut 的运行结论。房车流程固定为：

**车型外观 → 布局 → 选择预设风格 → 真实 AI 生成 1 张外观图 + 3 张内景图。**

这是一组静态方案图，不是视频编辑、Brief 转分镜或多媒体成片流程。视频旁白、字幕、音乐、数字人、剪辑时长、视频导出及继续编辑器交接不进入 P0 主链路。

### 5.1 画布、聊天与版本的分工

- **建议**：画布承载可定位的输入与结果，左栏提供本流程的明确入口，右侧聊天承载针对指定对象/版本的解释与迭代。
- **建议**：一次生成固定车型外观、布局版本、预设风格及其必要参数，形成同一批次的不可变输入快照；四张图属于这一批次，而不是分别读取不断变化的“当前选择”。
- **建议**：调整车型、布局或风格后创建新方案版本。晚到的旧结果保留原归属并标记，不覆盖新方案，不因画布当前选中另一个节点就改挂结果。
- **建议**：四张图共享空间约束，门窗、主要家具与分区关系按同一布局核对。实际生成成功不等于空间关系正确，仍需独立质量验收。

正式的数据字段、接口与状态命名由本产品的开发文档确定；上述是领域约束，不是从 CapCut 推定的后端 schema。

### 5.2 P0 必须是真实 AI 静态图

旧 `rebuild-prompt` 中“Mock 优先”的做法适用于原画布演示或交互搭建，不适用于房车 P0 的验收要求。房车 P0 必须使用经授权的真实 AI 图片服务，提交真实生成任务并取得可查看、可保存、可追溯的静态图产物。

占位图、固定样张、本地随机图或假进度可以用于明确隔离并标注的开发测试，但不能冒充正式生成结果，也不能作为 P0 完成依据。真实服务不可用时应呈现明确失败或阻塞，不得静默回退成 Mock 成功。

模型服务通过本产品后端及独立适配层接入；服务凭证仅在服务端管理。不依赖 CapCut 登录态、账号资源或研究中发现的私有能力完成房车生成。

### 5.3 最小异步与质量验收建议

- **建议**：分别显示提交、执行、成功、失败、取消请求和取消确认；不要在点击按钮或创建结果卡时提前宣告生成完成。
- **建议**：刷新后恢复已有任务而非重复提交；重试使用明确的去重机制，避免重复生成或重复计费。
- **建议**：验收真实任务与四张产物的对应关系；部分失败时如实展示缺失视角，保留已成功结果，并提供定向重试。
- **建议**：验收四图共同的车型、布局与风格一致性；若要求跨图一致性，需用真实模型样例验证，不能仅由提示词或 UI 参数推定。
- **建议**：验收版本切换、旧任务晚到、保存失败、重载恢复及结果文件可访问性。报价、费用授权与最终扣费记录各自校验，不从余额截图推算结算。

## 6. 后端契约与安全同步原则

### 6.1 私有接口不是本产品契约

本文刻意不列出 CapCut 私有接口路径、请求体或内部状态码。静态发现接口常量只能证明发布包中存在字面值，不能证明接口现行可用、权限适配、输入输出稳定、允许第三方调用或已完成计费验证。

房车产品应定义自己的方案、输入快照、生成批次、视角产物与任务生命周期，使用正式授权的模型服务和存储服务。不得将 CapCut 私有接口、内部工具名、数字状态码或取消返回值直接当作新产品的后端契约；也不得把本摘要当作访问或重放这些能力的授权。

### 6.2 研究材料的发布边界

本文件只同步脱敏摘要。原始报告、运行档案、截图、源码包、抽取模块、REA 原始证据包及终端日志继续留在受控研究环境，不随团队文档或产品源码整包发布。

不得附带账号信息、真实草稿/工作区/空间标识、会话或任务实例标识、浏览器凭证与存储、签名媒体地址、个人绝对路径或私有截图。即使源码来自公开发布的前端资源，也不因此将整包源码或原始 bundles 加入产品仓库。

如需复核原材料，应由有权限的维护者在受控环境按文件名与哈希核对，另行决定访问范围；不得通过公开附件、未脱敏截图或复制登录态补齐证据。原研究没有的网络关系必须保留“未验证”，不能用静态推断填成事实。
