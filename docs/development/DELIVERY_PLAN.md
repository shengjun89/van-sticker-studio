# 开发顺序、验收与团队交接

版本：2026-10-27。以下是依据确认需求整理的建议交付顺序，不是已承诺的排期、预算或技术选型。

## 1. 先读什么，怎么开始

1. 读 [产品规格](PRODUCT_SPEC.md)，确认 P0 / P1、不可越界规则及被覆盖的旧讨论。
2. 读 [现有实现](EXISTING_IMPLEMENTATION.md)，亲自核当前分支与未提交内容；不能从旧报告反写用户新改动。
3. 读 [画布交互](CANVAS_INTERACTIONS.md) 与 [架构建议](ARCHITECTURE.md)，将本次任务限定到一个垂直闭环。
4. 检查 [未决问题](OPEN_QUESTIONS.md)。阻断项写成具体问题，非阻断项继续推进，不替产品负责人造决定。
5. 在任务 / PR 中引用下表验收 ID，并写清“已实现、已实测、未验证”，附可复现步骤与同版资产标识。

原项目是已有真实模型的外观拉花工具，不宜重写掉所有已验证的模型、动作和直接编辑能力。新模型卡和生成任务逐步接入，避免以大规模 UI 替换掩盖底层数据未完成。

## 2. 建议里程碑与依赖

| 阶段 | 垂直交付 | 前置 / 退出条件 |
| --- | --- | --- |
| M0 数据与风险验证 | 首批真实车型目录、尺寸来源、空间包络；8 外观目录；真实 AI 的结构保真小样；固定机位试验 | 来源不能混版；列出缺失净空间；AI 真实输出若擅改布局不能假称风险已解决 |
| M1 画布与初始化 | 模型卡、两种模式、左右面板、单车型完整外观、8 预设、真实本地保存 / 恢复 | 无任何 AI 调用也可完成首段；刷新后恢复；现有模型动作回归 |
| M2 空间布局 | 10 白模配件、合法安装 / 嵌套、拖放预览、模板匹配、清空与快照、显式复制卡 | 不缩成品、不自动重排；真实不同空间可比较；几何修改锁定生效 |
| M3 真实四图闭环 | 登录门禁、成本确认、服务端异步任务、固定四机位、逐图状态、部分失败重试、版本归属 | 必须真实 AI；后台继续编辑；空间不一致拒为合格；刷新 / 断网重连有真实恢复策略 |
| M4 交付与权限 | 四图放大 / 下载、低模独立对象层级导出、权限开关、云保存 | 在 Blender / FreeCAD 实际导入验收；不接真实支付；同版来源可追溯 |
| M5 综合验收 | 从游客初始化到登录出图 / 下载的真实端到端演练 | 下列 P0 门槛有证据；未决阻断项解决；不以 Mock 测试替代真实服务与文件验收 |

M0 的真实 AI 小样应提前做，不要等画布全部完成后才发现结构约束无法满足。可以先交付单一经过核验的基线闭环，但不能因此宣称所有首批车型、B / C 或 8 预设都已完成。

## 4. 测试层次与证据

### 自动化

- 领域单测：场景版本、父子变换、边界 / 安装面、合法容纳、几何锁、快照、撤销隔离。
- 集成测试：本地保存恢复、鉴权 / 权益、生成幂等、任务状态持久化、部分失败重试、重复回调 / 乱序事件。
- 交互测试：卡内与画布手势冲突、视口往返、无焦点劫持、引用一致、空态 / 错误 / 重试。
- 导出往返：对象层级、单位、世界变换、版本哈希和包内清单。

现有项目可运行命令以仓库 `package.json` 为准：`npm test`、`npm run lint`、`npx tsc --noEmit`、`npm run build`。先记录当前基线结果，不将用户既有未提交失败误归本次。文档-only 更改需做链接 / 结构 / 敏感信息检查，不以无关代码构建替代文档审核。

### 真实外部能力

P0 至少一次完整真实四图任务及一次部分失败恢复演练。记录请求前确认、不可变源版本、各图实际输出、空间核查结果、预估与实际结算（服务无法给实际结算时标未知）、任务恢复行为。不要把静态服务端代码、注入上游响应的测试或示例图当成这份证据。

分享图核查必须以同版模型视图为依据。可以借助自动结构核查，但开发者不能仅因 AI 返回文件就标为合格。具体审核阈值与人工兜底需在 M0 / M3 试验后确认。

### 资产与性能

每次资产变更记录版本、SHA256、单位 / 坐标、来源、修改范围和回归视图。保留原始 CAD / Blender，不把网页增量修改冒充源工程同步。

帧率、显存、允许卡数、首次模型加载时间等数字尚未约定，应在目标桌面设备上测量后定门槛，不能编造已达 60fps 或无限模型并发。可采用非编辑卡缩略预览 / 限制活动渲染等架构建议，但实际体验要验。

## 6. 开发纪律

- 保护现有未提交代码和用户最新资产，不自动回滚旧模型；代码 / 模型 / 图册不同版要如实登记。
- 不复制剪映私有 API、认证信息、签名 URL、账号截图。研究仅用于交互与状态设计。
- 密钥只在服务端；不把真实钥匙写进文档、日志、浏览器或 Git。
- Mock 有明显标记，可用于开发和自动化，不能通过 P0 正式出图门槛。
- 不擅自移动布局、不因 AI 生成顺手改模型、不让静态图反过来覆盖真实几何。
- 实际设备能容纳不代表允许安装；不根据低模尺寸给出承载 / 合规 / 施工结论。
- 对未决项留言时用 [问题编号](OPEN_QUESTIONS.md) 和具体影响，负责人可以直接逐项回复，不必重启长访谈。
