# 画布与交互契约

版本：2026-10-27。本文产品行为来自已确认访谈；按钮细文案、快捷键组合、触控手势和默认卡尺寸如未明确，均不视为已拍板视觉稿。

## 1. 页面骨架

- 中央无限二维画布：容纳模型方案卡、四图结果卡；允许多个方案并排比较。
- 左侧窄图标栏 + 可收起面板：“车型 / 造型”“配色拉花”“配件库”，同一时间只展开一个。
- 右侧 AI 对话：保留当前目标引用、上下文完善、模板 / 风格建议、生成确认。
- 全局任务提示不抢焦点。额度、保存范围和当前撤销范围应清楚可见，具体位置由 UI 设计确定。

卡片是工作流产物，不是每个家具的二维节点。配件只存在模型场景内；不要求用户给家具 / 图片手动连线。

## 2. 两种操作模式

| 行为 | 浏览画布 | 编辑模型 |
| --- | --- | --- |
| 默认对象 | 画布 / 卡片 | 当前卡内部三维场景 |
| 进入 | 默认；或编辑结束 | 双击模型卡 |
| 视口 | 自由浏览无限画布 | 当前卡在原画布可用区居中放大 |
| 其他卡 | 正常显示 | 弱化但不移动、不重排 |
| 模型交互 | 不能误移动配件 | 选择、拖动、旋转配件；视图切换 |
| 左栏 | 选择目标或引导进入编辑 | 作用于当前模型；无目标不执行 |
| 右侧 AI | 显示选中目标引用 | 保留对话与引用 |
| 撤销 / 重做 | 卡片操作 | 当前模型布局 / 外观变更 |
| 退出 | 不适用 | Esc 或“完成”，恢复进入前的画布视口 |

实现必须把事件作用域隔开，不能一次拖动同时平移画布、移动模型卡和移动配件。按 Esc 时，如果有正在进行的临时拖动 / 弹层，建议先取消该临时操作，下一次再退出编辑；此优先级是实现建议，需交互验收确认。

三维编辑仍在原页，不跳转大型独立编辑器。卡片位置不能因放大编辑被写成永久移动。右侧对话及左侧展开面板占据的空间应计入居中范围。

## 3. 主要操作链

### A. 首次进入

1. 可跳过填写最高身高、人数、场景。
2. 选择真实车型基线与外观；缺少可信基线的组合不能假装可选。
3. 实时切换 8 套配色 / 拉花；无 AI 请求和额度变化。
4. 初始化模型卡并自动选中，输入框出现引用。
5. 进入布局阶段，按车型选择默认 / 推荐模板，再二次编辑。
6. 游客自动本地保存并显示“仅保存在本机”。

引导采取几屏或在左面板完成、是否首次自动进入编辑等具体布局未确认；不得把这份链路误写为已确认逐像素稿。

### B. 布局拖放

1. 双击目标模型卡进入编辑，默认去顶俯视。
2. 从配件库开始拖动。未进入有效模型区时不创建正式对象。
3. 命中模型后显示半透明预览，依据配件安装规则确定高度 / 朝向。
4. 评估吸附、车壳边界、家具碰撞、合法柜内容纳；实时显示可放或具体原因。
5. 松手在合法位置才提交一个模型变更，并进入当前模型撤销历史。
6. 非法位置或拖出模型区取消，只提示原因，不挪旧配件、不变形。
7. 一键透视检查；去顶 / 隐藏侧墙仅是显示状态，不删除导出结构。

已有配件移动同样需要临时预览、验证和提交 / 取消。选择父柜或子设备的明确入口必须存在，不能嵌入后再也选不中设备。

### C. 调整底盘

无布局：在当前卡切换真实基线或允许的空间外壳参数。

有布局：空间参数锁定，说明原因并提供“清空布局后修改”。先二次确认，再保存完整快照和清空配件；保持底盘、外观和图片。随后在同一卡修改底盘，不自动重排旧配件、不新建方案卡。

恢复快照必须同时恢复其车型与布局，图片保留自己的来源版本，不强行改成“当前”。恢复动作的撤销分组、快照数量上限见未决问题。

### D. 比较方案

用户显式“新建方案”可复制当前或重新初始化。复制当前车型、外观、布局，不复制成一次新 AI 生成，不扣额度。原卡及已产生的图片不受影响。

可以在不同卡上布置不同真实空间。结果比较不能只换图片而共用一份被覆盖的模型数据。当前卡替换模板不隐式建新卡；已有布局被替换前的确认与快照规则待拍板。

### E. 生成四图

1. 选中模型目标，选择预置装修风格。
2. 明确展示“1 张外观 + 3 张内景”、预计消耗、剩余额度；不足时阻止提交并解释。
3. 未登录先登录；成功返回后不能绕过用户确认自动多次提交。
4. 用户主动点击提交，锁定源版本和风格 / 固定机位，创建四图结果卡。
5. 后台逐图更新真实状态；用户可继续布局或切换卡片。
6. 完成只发提示；点“查看结果”才定位结果卡。
7. 单图可放大，按权限下载。来源模型被编辑后，相关旧图标“待更新”。

四图结果卡是一次提交的容器；具体四图网格比例和各内景机位名称待设计，不凭空决定。卡片整体可移动，单图不成为必须手动组织的四张独立画布卡。

### F. 部分失败与重试

保留成功图；失败图显示真实原因。用户点重试时列明失败项张数与新预计消耗，由其确认后仅提交失败项。不能把已成功图再次计入生成，也不能静默降低规格。每个重试尝试要有可追溯来源，不覆盖历史计费证据。

## 4. 前台状态不等于任务状态

| 场景 | 允许 / 要求 | 禁止 |
| --- | --- | --- |
| 生成中改布局 | 新模型版本继续编辑；旧任务仍用旧版 | 全局锁画布；把旧任务改指向新版 |
| 切换到另一模型卡 | 对话引用随当前选择更新；任务归属不变 | 将结果挂到当前刚选中的卡 |
| 完成但用户在编辑 | 更新卡和非阻断提示 | 自动跳转或退出编辑 |
| 撤销一个模型修改 | 回退模型编辑历史 | 回滚已提交服务任务、伪造额度退款 |
| 断网 / 刷新 | 明确保存和任务恢复状态 | 空进度一直转、伪造保存成功 |
| 无目标输入生成意图 | 要求选择明确目标 | 猜测某张卡并直接扣额度 |

后端任务状态名称和转换属于架构建议；“真实状态”“部分重试”“不阻断”“版本冻结”为确定约束。

## 5. 撤销范围与显示状态

编辑态撤销当前模型布局和外观；浏览态撤销卡片操作，界面明确标注范围。生成任务使用独立取消入口，不通过 Ctrl / Cmd + Z 返还额度。

进入 / 退出编辑、隐藏屋顶、相机切换等显示行为不能悄悄删结构。显示状态是否进入单独视图历史、保存为项目偏好以及卡片删除规则尚未完全确认，见待决清单。

## 6. 关键空态和门禁

- 无模型卡：引导初始化，不显示可直接提交的生成按钮。
- 未选中模型：左面板和对话提示目标，不误作用于上一张卡。
- 有布局：空间参数显示锁定原因；配色 / 拉花保持可用。
- 没有兼容模板：说明不支持，允许保留空布局手动开始的策略需确认，不用不适配模板假冒成功。
- 缺 AI 配置 / 服务失败：显示真实失败，不输出示例图作为成功结果。
- 会员权益不足：显示受限能力和升级入口，但 P0 不发起真实付款。
- 本地存储失败 / 容量不足：明确未保存风险，不再显示已保存。

## 7. 尚未拍板的交互，不应擅自开发成既定规则

卡片删除与关联结果、运行中任务的处理；触控与轨迹板具体手势；模型卡尺寸 / 缩放上限；结果卡精确布局；模板替换确认；快照数量 / 版本管理入口；聊天历史的作用域；相机预设的具体参数。参见 [待确认问题](OPEN_QUESTIONS.md)。
