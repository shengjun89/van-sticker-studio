# van-sticker 产品开发规格

版本：2026-10-27 · 需求基线 v1 · 状态：产品负责人已确认的访谈结论，尚非功能完成声明。

## 1. 产品目标与边界

让用户从真实车型依据出发，先做有吸引力的房车外观，再快速搭建可以调整、比较的车内空间，最后获得装修风格效果图和可继续编辑的低模。

核心闭环：**选车型 → 实时外观 → 适配布局模板 → 拖拽调整 → 选预置风格 → 主动生成 1 张外观 + 3 张内景 → 分享 / 按权益导出模型**。

P0 是有真实尺寸依据的概念设计工具，不是施工设计系统。模型中的尺寸、吸附和碰撞检查不能被描述为实车复尺、承载、设备安装、道路公告或开料批准。AI 图片不能作为尺寸依据。

本文“必须”指已确认产品要求；技术实现建议见 [架构](ARCHITECTURE.md)，未决项见 [待确认问题](OPEN_QUESTIONS.md)。现有代码能力见 [实现盘点](EXISTING_IMPLEMENTATION.md)，不得把目标清单当成已实现清单。

## 2. P0 范围

| 领域 | 必须交付 | 不包含 |
| --- | --- | --- |
| 车型与外观 | 首批真实车型基线；外壳造型参数；8 套预枚举配色 / 拉花；低模实时显示 | 无依据地拉伸轴距 / 轮位；把衍生 C 型概念冒充公告车型 |
| 空间布局 | 车型适配模板；10 类基础配件；拖放、吸附、空间检查；俯视 / 透视切换 | 从文字自由生成家具位置；精细施工节点和机电设计 |
| 画布 | 无限画布；模型方案卡；四图结果卡；两种操作模式；自动来源关联 | 专业视频剪辑器；用户手动连线搭工作流 |
| AI 图片 | 真实图像服务；单个预置装修风格；固定机位 1 外观 + 3 内景；逐图真实状态 | 用占位图或模拟进度验收；P0 必经的多风格 AI 对比 |
| 保存与交付 | 游客本地自动保存；登录门禁；模型版本与图片来源；按权益下载低模与图片 | 真实支付、自动订阅扣款、精装图反建高精三维 |

自然语言追加风格描述放 P1；自然语言增删 / 移动配件暂缓。P0 对话侧重完善需求、推荐模板 / 风格、解释方案，以及经用户确认发起出图。

## 3. 初始化：真实基线与好看的外观

### 3.1 白模的定义

“初始化白模”是车辆底盘 / 基础车体 / 外壳，不包含已经布置好的家具和装修。家具在布局阶段添加；默认模板也属于布局阶段，不偷塞进初始化底盘数据。

用户希望初始化依据首批真实底盘系列的公告数据库。远端已存在 `lib/announcement-db.json` 与入库门禁：35 条记录中 24 条字段完整、11 条部分缺失。它们不自动等于本次指定系列的可用基线：完整行备注仍有承载式车身、具体底盘未确认等限制，程序白模也未证明与真实驾驶室 / 轮位一致。同版净空间和首批采用集合仍需交接；不能凭空补齐 B / C、轴距、顶高组合。详细证据见现有实现盘点。

### 3.2 几何规则

- 每个真实基线固定轴距、车轮位置、驾驶室位置；公开界面车型名称按仓库去品牌化规则通用化，技术来源保留必要公告型号，不恢复模型品牌几何。
- 长轴 / 短轴切换是切换对应的真实车型基线，不是拉伸现有底盘。
- 圆润 / 硬朗主要修改车厢上装和外壳造型；C 型车及其他造型衍生从首批基线生长。
- 衍生外壳需要独立版本和可用空间描述，不因此获得真实公告或可制造状态。
- 首批参数化覆盖这一组车型，不承诺任意品牌、任意车壳都可编辑。

### 3.3 8 套配色 / 拉花

8 套为提前写在代码中的枚举方案：切换立即改变模型，不排队、不调用 AI、不扣生成额度。布局存在时也可随时切换。

用户主动选择 AI 外观出图时才调用真实服务，出图沿用所选配色和拉花。模型上的预设切换与付费 AI 出图是两个独立操作。

现有可访问版本只定位到 4 个示例，不能把它们凑成已完成的 8 套。确切的 8 套内容需补齐来源；不得以历史 10 张 AI 概念图替代。

## 4. 从模板进入布局

### 4.1 可跳过的用户信息

首版只收集最高使用者身高、常用人数、主要使用场景。全部可跳过，不阻断进入画布；进入后可补充或修改。暂不收体重或复杂身体测量。

没有上下文时，加载该车型的通用布局；有上下文时，从兼容模板库推荐更合适的模板，再由用户二次编辑。不是要求用户用语言描述每个物品的空间坐标，也不是任意生成后假称已适配。

修改上下文不自动重排现有布局。推荐与实际应用分开；切换模板的已有配件替换确认细节见未决项。

### 4.2 10 类基础白模

| 类别 | P0 表达与放置重点 |
| --- | --- |
| 床架 | 落地；真实占地；后续可支持定制净宽 |
| 卡座 | 落地；座体空间；不推定已批准行车乘坐 |
| 餐桌 | 预设安装形式；不允许无支撑悬空 |
| 厨柜 | 落地 / 靠壁规则；为设备保留合法容纳区 |
| 储物柜 | 安装面、占地、可用容纳区 |
| 吊柜 | 靠壁定位；自动高度与初始朝向 |
| 冰箱 | 固定成品尺寸；可作为柜内独立设备 |
| 空调 | 按具体机型区分安装形式；不能把所有空调都塞进吊柜 |
| 马桶 | 卫浴相关基础白模；安装与排污只表达待核接口 |
| 淋浴间 | 作为空间占用 / 分区白模，不代表防水施工设计 |

每类先做一个基础模型。品牌、型号与高级配件以后扩展，不为了外观精细而推迟空间闭环。

### 4.3 拖放与空间约束

- 成品设备保持真实尺寸，只吸附合法位置；放不下明确提示，不强行缩放。
- 床架、柜体等定制件后续可以按净宽参数化；P0 不必先开放精细尺寸编辑。
- 按类型预设地面、侧壁、顶部等安装面，拖入时自动确定高度和初始朝向；用户主要调整平面位置、旋转。
- 拖动时显示半透明模型、吸附位置、可放 / 不可放及原因。松手才提交；非法位置或拖出模型区取消，不留下幽灵对象。
- 不自动移动已有配件，不穿墙、不无支撑悬空。
- 柜内设备形成父子关系，移动柜体时随动；设备仍能独立选中、取出或替换。
- 合法容纳和非法碰撞必须区分；导出保留独立对象与父子层级。
- 简化空间检查不等于连续运动、受力、通风、排水或人体工程全面验收。

布局默认去顶俯视；必要时隐藏遮挡侧壁，仅改变显示，不删除结构。支持一键透视三维检查。布局图与低模视图必须来自同一场景，不能各画一份独立数据。

## 5. 方案卡、修改与快照

### 5.1 新建原则

**只有用户明确“新建方案卡”才新增模型卡**，可选“复制当前方案”或“重新选车型初始化”。复制包含车型、配色、布局，原卡不变，不触发 AI 或扣额度。

普通编辑和替换不自动分叉。此前“换模板就自动新增独立模型卡”的讨论已被这条后续决定覆盖。需要比较时，由用户显式复制后修改。

### 5.2 有布局时的锁定

存在布局时，只锁定车型、轴距、顶高及影响空间的外壳造型；配色 / 拉花等纯视觉修改不锁。

用户要重新修改底盘，必须先确认清空布局。在当前卡先存可恢复的完整快照，再移除布局配件；不删底盘、配色和已有图片，不新增卡，不自动替用户重排。

恢复时车型和布局一起恢复，不能把旧布局直接套进新车型。已有图片始终保留来源版本。

### 5.3 图片与版本

出图锁定提交时的模型版本。编辑模型后，受影响的旧图显示“待更新”，不覆盖、不自动重生成。

每个模型方案可有多个历史版本和多个四图结果卡。低模、平面布局、四张 AI 图和导出文件必须能追溯到确定版本，不能混用“当前模型”和“历史图片”作为同版交付。

## 6. 真实 AI 四图闭环

### 6.1 输入与构图

P0 用户先选一个预置装修风格，然后一键生成 **1 张外观 + 3 张内景**。风格示意卡不扣额度；外观保留当前外壳、配色和拉花，内景采用所选风格。

使用受控固定机位，不要求用户编辑专业镜头，不提供任意当前视角作为 P0 正式出图入口。机位应适配模板 / 布局；具体位置和可视标准待资产试验确定。以后再处理复杂布局的特化机位。

### 6.2 不可越过的空间约束

AI 只允许改变材质、配色、灯光和装饰；不能擅自改变门窗及家具的位置、尺寸、朝向。布局调整必须回模型卡操作。

单靠提示词不能保证这些约束。服务接入要验证模型投影、结构参考或其他真实控制能力，并审核结果；不一致的图片必须标记不合格，不进入合格分享交付。审核的自动化程度与阈值尚待技术验证。

### 6.3 用户主动提交与成本透明

- 按钮显示图片张数、预计消耗、剩余额度；用户主动点击才提交。
- 聊天、拖动配件、切换配色 / 风格示意不自动出图。
- 额度不足明确提示，不擅自减少张数、降低规格。
- 提交后立即创建四图结果卡，并按图显示真实等待 / 运行 / 成功 / 失败等状态，不能用假百分比冒充服务进度。
- 部分成功保留成功图片，只重试失败项；展示失败原因、重试张数及预计消耗，经用户点击后重试，不整组重跑或自动无限重试。
- 取消任务与撤销分开；取消、实际计费与额度结算规则待确认，不承诺“取消必退款”。

### 6.4 完全后台运行

生成中可继续编辑、切换卡片及操作画布；始终使用提交时冻结的版本。完成只更新结果卡并提示，不跳转、不强制定位、不打断编辑；用户点“查看结果”才移动视口。

每次提交只新增一张四图结果卡，固定呈现 1 外观 + 3 内景，自动关联源版本；不新增模型卡。整组可移动，单图可放大、按权限下载，不要求手动连线。

## 7. AI 对话的目标引用

对话绑定当前选中的模型方案卡，并在输入框显示明确引用。首次创建后自动选中。没有明确目标时不能执行修改或渲染，必须先选目标。

任务提交时固定目标和版本。随后切换选择不能把任务或结果改挂到另一个方案。对话中的推荐 / 解释不能直接触发扣额度的任务。

## 8. 保存、登录、下载与商业化

游客可以选车型、摆配件并本地自动保存，明确显示“仅保存在本机”。AI 出图、云端保存、会员模型下载时再要求登录。登录后迁移本地工程及冲突处理尚未确定，不能以假云保存代替。

可编辑三维源模型下载是主要会员权益。P0 导出底盘、外壳、配件低模，保留独立对象、空间关系和层级，以便在 Blender / FreeCAD 继续工作。具体格式及 FreeCAD 可编辑层级待验证；不把网格导入冒称原生参数化 CAD。

AI 静态图用于选风格和分享，不反向重建成精装三维。基础图片下载、高清 / 无水印权益分别处理。模型导出、高级配件、图片下载和 AI 额度分别控制。P0 仅预留收费入口与能力边界，不接真实支付。

## 9. 已覆盖的早期讨论，禁止误实施

| 旧讨论 | 最终基线 |
| --- | --- |
| 首版只做内饰，外观以后做 | 外观及 8 套配色 / 拉花属于 P0 核心 |
| 换模板自动新建模型卡 | 仅用户显式新建才新增模型卡 |
| 先生成 2–3 套风格，再生成分享组 | P0 选预置风格后直接 1 外观 + 3 内景，多风格比较不是必经步骤 |
| 用户选当前视角或复杂机位 | P0 固定受控机位 |
| 对话直接移动配件 | P0 以拖拽布局为主；自然语言改布局暂缓 |
| 白模已包含家具 | 初始化是底盘 / 车体；布局阶段才加入家具 |
| Mock 默认即可正式交付 | P0 必须真实 AI 服务出图，Mock 仅开发测试 |

## 10. 完成定义

开发者应按 [交付与验收](DELIVERY_PLAN.md) 的可观察结果交付，而不是仅给可点击演示。至少跑通真实车型依据 → 外观 → 模板 / 手动空间调整 → 保存恢复 → 真实四图 → 版本关系 → 权益边界 / 低模导出；遇到数据、图像服务、空间保真未决，明确标记不通过，不编造成功。
