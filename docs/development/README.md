# van-sticker 项目开发文档

更新：2026-10-27 · 产品需求基线 v1；本次为待评审的扩展开发规格。

这套文档把房车产品访谈、现有代码 / 模型盘点和剪映 AI 工作流研究整理成团队可接续开发的依据。**它不是功能已完成的报告，也不是施工图或车型公告。** 产品访谈已结束，未明确的问题集中留言，不再阻断已明确模块的开发。仓库 constitution / AGENTS / CONTRIBUTING 的治理、生效、claim、四门禁与独立评审规则保持不变；本提案合入前不迁移既有任务或自行扩大权限。

## 一句话目标

基于真实车型的房车设计工作流：**选车型 → 实时外观 → 快速车内布局 → 选预置装修风格 → 真实 AI 生成 1 外观 + 3 内景 → 分享 / 按权益下载可编辑低模**。中央无限画布、左侧工具与折叠面板、右侧 AI 对话；不做专业视频编辑器。

## 四种信息，不能混为一谈

1. **已确认需求**：产品负责人在本次访谈明确回答的内容，汇总于产品规格与交互契约。
2. **当前实现事实**：静态代码 / 本地资产盘点；不等于真实服务已经验收，更不等于所有文件已在远端。
3. **技术建议**：可供实现的分层、schema、任务策略；需要工程验证和评审，不擅自升级为用户决定。
4. **未决问题**：来源、机位、格式、删除 / 结算等尚未拍板；见编号问题，不用“默认如此”填空。

访谈中的后续纠正覆盖早期讨论。特别是：外观在 P0；8 套外观实时无 AI；仅显式新建增加模型卡；固定四机位；单个预置风格直接四图；真实 AI 不能用 Mock 验收。

## 接手第一天

先确认自己分支、未提交修改和资产修订，再看现有实现盘点；按仓库流程冻结验收 ID 后领取小闭环任务。保留已有车门、车窗、雨刷、拉花等有效行为，不用旧模型覆盖当前用户资产。根 README 的现有外观工具说明与本目录的新 RV 工作流目标分开，冲突按生效规格处理，不能用分支草案替换既有冻结验收。公开界面品牌继续使用 MXGARAGE VAN，来源数据与产品外显命名分开。

关键不足必须透明：远端已有公告入库与 Body Lab 参数化示意基础，但数值完整不等于指定底盘、驾驶室和轮位已经真实匹配；完整 8 套外观来源仍待确认。旧本地副本与远端明显不同，不能以旧本地判断覆盖远端。现有拉花生成流不等于装修四机位异步任务，不要把缺口藏进“已接入”。

代码修改的测试入口以 `package.json` 为准；本套文档维护时须检查内部链接、JSON 索引、验收映射及明显敏感信息。文档检查不能替代仓库既定四门禁，也不授予读取私有身份配置的权限；检查未运行时如实记录。

## 研究材料如何使用

剪映研究只作为公开可讨论的交互和状态设计参考，不复制其私有接口、凭据、签名地址或业务后端。本次同步的是脱敏总结与来源指纹，不包含原始源码包、私有草稿截图、账号信息、原始网络凭据或大型分析图。

旧剪映通用 rebuild 提示词不是本项目规格，尤其其中 Mock 默认路线不能覆盖本项目真实 AI 的 P0 要求。想让 AI 辅助开发，可直接使用以下任务说明，并补上具体任务和验收 ID：

```text
先阅读 docs/development/README.md、PRODUCT_SPEC.md、EXISTING_IMPLEMENTATION.md。
按本次任务再读 CANVAS_INTERACTIONS.md、ARCHITECTURE.md、DELIVERY_PLAN.md。
把已确认需求、当前实现、技术建议和未决项分开，不从旧剪映提示词导入未批准功能。
先核当前分支与未提交修改，保留用户代码和最新模型；只实现本次验收ID对应的闭环。
不擅自改变用户布局，不自动出图/扣额度，不用Mock宣称真实AI或云保存成功。
未决项在OPEN_QUESTIONS.md引用编号留言；可独立推进的部分继续做。
交付实现范围、运行证据、资产版本、剩余风险；不要仅给占位UI或口头完成声明。
本次任务与验收ID：<填写>
```

## 维护方式

需求变更先更新相应正文与 [变更记录](CHANGELOG.md)，同步需求索引 / 验收用例，再在任务或 PR 中引用。未回答的问题不能直接删掉当作解决。新增技术选择宜单独 ADR，标清替代项、验证依据和未解决风险。
